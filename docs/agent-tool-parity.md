For a new AI retest of a directory that already has fast-mode reports, `use_progress_evidence=false` creates a new round. Prior reports are retained until replacement reports are successfully generated. Continue preserves only progress from that round, together with the current file's saved investigation. A model transport failure preserves the pending user instruction; older saved sessions recover it from user events.

An active blocked checkpoint takes precedence over old 100% progress and completion summaries in frontend session storage. The visible Continue action submits the resume request after its status preflight; a stale frontend completion marker cannot silently cancel it. Both the button and chat Continue have regressions that seed blocked model transport with old completion progress and verify `doc.retest.agent.message` submission.

The model view contains queue counts and a short path window. Full source lists remain in durable state and are accessible through `list_reports` pagination. Generic `workspace_tree` truncation no longer prevents the Agent from obtaining notice paths. The source's paragraphs, tables, hyperlinks and labeled bare domains contribute to document context; legacy binary DOC inputs use the native Word conversion worker.

Original HTTP requests retain their method, application headers and payload, while the HTTP broker generates transport headers such as Host and Content-Length. Original parameter payloads are available to replay tools. Standard login checks reuse the page's cookies and hidden form fields, submit only the credentials provided in the notice, and keep response cookies out of model evidence. Direct URL tasks retain the exact staged input and pending operation so Continue can resume them. Report-generation tools persist the generated paths in the same queue as the saved results; explicit report deletion covers inconclusive and unmatched generated reports too.

Notice processing now has four stages: rewrite, rectification notice, disposal document, and PDF. Authorization letters are no longer required or generated. ZIP, 7z, RAR and nested archives are extracted and verified, their extraction checkpoint is saved, and the source archive is deleted before classification and rewriting. Failed extraction preserves the source archive; an already consumed selected archive can resume from its recorded parent workspace.

Safety and evidence requirements continue to apply: host Python and arbitrary external sqlmap are not restored, target scope and cancellation are enforced by Rust, and a successful tool call or HTTP 200 alone never establishes a vulnerability judgement. Missing original request parameters remain explicit evidence gaps. Images that do not expose readable text still require an original PoC or equivalent verifiable evidence.

Regressions cover pagination beyond the workspace tree limit, a model-selected fresh AI queue with existing reports, saved user-goal recovery after transport failure, resume after restart, legacy HTTP context extraction, complete-answer SSE connection resets, and Continue/chat frontend routing. Native UI clicking and a full rerun against the user's production directory are separate from these isolated fixtures.

Continue is enforced by the current user request in Rust. When the model proposes run_retest_queue(use_progress_evidence=false) during a resumed generation, Rust normalizes it to true before scheduling and preserves the existing round mode and current-file evidence. An explicit new user round still resets the queue. Status preflight also updates frontend lifecycle and saved checkpoints before checking busy flags. The reproduction uses a copy of the actual failed TLS notice and both persisted session states, with the currently configured real model; local model fixtures alone do not establish provider compatibility.

The additional tool corrections cover relative HTTP paths, repeated query/form fields, automatic JSON/form encoding, original notice context in Python probes, TLS handshakes on the reported host and original explicit port (or TLS default 443), concurrent bounded stdout/stderr draining, typed unavailable/skipped failures, exact or conservative HTTP request counts, original ffuf queries and trailing slashes, and rejection of missing ffuf result files or truncated SQL comparisons. ffuf no longer sends automatic calibration requests, and its discovery observations cannot independently verify a reported vulnerability. SQL uses the available request budget and records failed attempts too. A saved current-file checkpoint resumes directly into the model's investigation/judgement; historical outer chat cannot re-plan it from scratch. Windows state-file replacement retries temporary reader sharing conflicts without deleting the original.

The current request generation also polls backend status while its IPC response remains pending. Only a terminal or blocked snapshot from the accepted backend generation can release that busy state; earlier snapshots cannot cancel a new turn. Same-host TLS URL aliases are normalized before duplicate detection, preserving the single bounded retry for legacy skipped observations.

Investigation now exposes tool_status and install_tools as well as the session tools. When a required optional runtime is absent, the Agent can prepare that specific locked package without abandoning the current file and its evidence. Only known nmap/ffuf packages and the builtin SQL validator are accepted; tool installation never counts as vulnerability evidence.

The general Python fallback now accepts 256 KiB scripts, 100 broker operations and a five-minute run. HTTP timeout defaults to 30 seconds and honors script timeout up to 90 seconds, including tuple-style requests timeouts. It supports multipart files, Basic auth, request/session cookies, form/query repeated fields, raw bodies, response encoding and iteration, classes and normal string formatting, compression and data-processing standard modules, and tcp_exchange/tls_exchange plus socket/ssl stream sessions on the reported host and port. Reproducing a protocol no longer requires disguising it as HTTP. Dependencies can be requested with PyPI distribution/version requirements through packages; the resolver downloads compatible CPython 3.13 Windows x64 wheels with their dependencies, checks PyPI digests, records the resolved inventory and installs into the probe's isolated environment. If no compatible wheel exists, the error identifies the library/version gap for model repair. The copied standalone script reuses the same request/socket compatibility layer.
Routine consecutive status messages are grouped in a default-collapsed running-record disclosure, with count, latest action and timestamp. Expanding reveals all original statuses in a bounded scrolling area. Errors, approvals, blocked prompts and final results remain visible in the timeline.

The Python fallback supports common socket.create_connection/connect/sendall/recv and ssl context wrapping through persistent Rust-managed protocol channels. A real AppContainer test keeps one connection through a banner and two request/response exchanges. Another test requests BeautifulSoup outside the built-in package lock, resolves/downloads its PyPI dependencies, and runs its parser. The slow-response/multipart test waits 13 seconds before its HTTP response and succeeds with timeout=20, proving the previous hardcoded 12-second bug is fixed. Library downloads remain outside the process's target network scope; installed distributions are recorded with version, artifact URL and digest for the probe environment.

Any status event with a body now has a disclosure, including plans shorter than 80 characters. The actual text is preserved in a wrapping body; the inspector offers the same disclosure. Tests cover mouse and keyboard toggles of a short plan.

Notice processing checkpoints are stored under koi-data/.koi-runtime/notice-process-state, keyed by the normalized selected directory. Context is propagated to background workers. Legacy .koi_notice_process_state.json files migrate only after a validated atomic write, and classification prepares the relocated checkpoint before moving a company directory. Cleanup validates completed outputs and includes an extraction-only parent checkpoint once all child notice checkpoints are complete. Incomplete checkpoints remain available in internal storage. User JSON files and formal notice/PDF/disposal artifacts are not cleanup candidates.

Failed retest output after an inconclusive judgement remains blocked and resumable with the exact evidence. A pending current-round queue cannot be presented as completed merely because a model reflection returns no operation or reaches its continuation limit.

## Tool execution audit on 2026-10-09

The audit checks declared tools against executors, original Python behavior, actual network operations and durable evidence. The changes normalize arguments/args/parameters/input and JSON function-call envelopes, classify structured success=false as operation failure, add complete notice pagination and later finding discovery, preserve model-supplied Python context, and count requests already sent by composite tools when a later step fails.

HTTP and preset tools now share their Rust cookie session with Python probes. Anonymous authorization-boundary checks use a separate cookie jar. Standard login follows same-origin redirects and resolves relative form actions against the final page; GET/POST methods, unquoted attributes and hidden fields are preserved. SQL differential verification accepts the original GET/POST JSON/form request and a selected parameter. Missing ffuf can fall back to native HTTP checks of the original/model-selected short path list, with engine identity recorded. Page collection includes same-origin form/link/JS endpoint candidates. Presets return check-specific observations for directory indexes, fingerprints, response headers, frame policy/CORS, schemas, source maps, reflected payloads, file signatures and external redirect locations. HTTP methods executes both OPTIONS and TRACE.

Saved result/report/inconclusive checkpoints can generate reports without retesting a target. Session-state and tool-status diagnostics work even when the selected directory is temporarily unavailable. Python fallback adds scoped UDP datagrams alongside TCP/TLS, with actual binary evidence and the same behavior in copied scripts. Wheel resolution retains dependency grouping, membership operators, optional extras and repeated direct version constraints; unsupported dependency markers produce an explicit error rather than silently dropping a dependency. Full dependency backtracking and arbitrary source builds are not implemented.

Validation uses real localhost HTTP/TCP/UDP services and Windows AppContainer, including cookies shared from HTTP to Python, UDP binary exchange, and actual PyPI installation followed by Python execution. Model-provider envelopes are tested through the complete model-to-tool-to-evidence loop. The 29 legacy preset IDs remain present; current capabilities and remaining environment limits are recorded in output/real-continue-verification/agent-tool-audit.json. A reflected XSS payload alone does not establish browser JavaScript execution, and advertised HTTP methods alone do not prove a destructive method can modify data.

## Canonical tool directory and completion choices

The current Agent advertises 28 executable session tools. Duplicate legacy retest_all_reports/retest_report names are removed; queue work uses run_retest_queue and single-source work uses retest_source_file. The model receives a separate available_tools list and preset_checks data: preset tool_id values are check_id arguments to run_preset_check, never executable tool names. Invalid model tool names are corrected before target requests or failed tool cards are created. The generic JSON envelope parser remains for current providers, without mapping old tool names to new tools.

Model replies and operation reflections can return follow_up with a question and label/value options. The backend validates/persists the question; the UI adds custom input. End appears only if can_end_task verifies all scheduled sources, current-generation operations and required report artifacts complete. Ending preserves reports/evidence, records task_ended and rejects Continue for that finished task. Incomplete or blocked work cannot be ended through this action.

Reports and the Agent UI share the same recorded tool output formatter. Cited TLS/Nmap evidence includes its actual protocol/cipher/certificate output; HTTP and Python evidence preserves actual response/result information. Reports use multiple bounded figures with readable text and include selectable original evidence. Model conclusions are excluded from evidence figures. Figures have separate relationships and measured sizes to avoid overflow.
