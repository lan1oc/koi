# Agent 报告阶段反复中断修复（2026-10-16）

当前失败会话为 `session-1791772747239-n5g3vk`。排查直接读取后台持久化状态、原通报截图及工具记录；没有替原会话重跑真实网站。

## 原因

1. 界面的“复测通报并生成报告”是整个单文件流程的工具名。最近一次后台失败实际发生在计划校验：原截图的 Nmap 输出明确关联目标主机与 `6443/tcp open ssl/http`，本机 OCR 输出为 `6443 / tcp`，主机后使用中文括号。目标提取仅收集正文 URL，丢失原截图的显式端口；模型每次提出 6443 都被拒绝。失败断点没有已通过校验的问题列表，所以点击继续又回到同一个计划修复循环。
2. 单独调用 `generate_reports` 恢复 Agent 判定时，摘要可能仅存在于 `result_data.summary`。旧代码把缺失的顶层 `summary` 当作 JSON null 传给报告请求的 String 字段，形成确定性的参数解析失败；旧前端包装的嵌套断点也没有被展开。
3. 证据图自动换行使用 UTF-8 字节索引，却固定以 `boundary + 1` 跳过空白。全角空格 U+3000 或不换行空格 U+00A0 会产生非法字符串切片，导致写报告的执行线程 panic。
4. 后续轮次重复返回已有问题 ID 时，旧代码先校验模型重新描述的目标，再保留原问题。重复字段中的额外端口或无效目标会在最终判定/结束调查前再次挡住流程。

## 修改

- 提取原通报中的 Nmap 主机与开放 Web/TLS 端口，兼容 OCR 的分隔空格及中文括号。端口必须关联到同一原文扫描块内、且已存在于原通报 URL 的主机；关闭端口、其他主机、其他截图及非 Web 服务不自动加入范围。仍由工具执行器逐次检查实际请求目标。
- 已保存的问题 ID 保留原始目标与验证标准，仅校验新问题并合并；最终判定不能因重复描述退回计划阶段。
- 报告工具展开实际文件断点，对摘要使用 `result_data.summary` 回退，兼容缺失或 null 的历史摘要；保留具体报告失败原因及已保存判定。
- 证据图按空白字符实际 UTF-8 长度换行，不修改原始证据正文。
- 增加真实 Windows 报告锁定失败后重试测试，检查旧报告、原通报及结果保存行为。
