# 通报队列、报告卡片与工作台布局修复（2026-10-12）

用户反馈报告已经生成却似乎仍在复测，报告路径显示拥挤且不能打开；随后要求每份通报明确区分，增加本份与总进度，改善侧栏，并保留原有模式和审批操作。

## 实际定位

截图中的“14:57:14 生成报告”对应原事件 `trace-1791773745028-69`。原事件时间为北京时间 10:55:45，报告属于 YX 激活码接口通报；后续真正处理的是同企业的 Chronograf 通报。原生事件使用数字时间戳，旧前端只接受字符串，因而将轮询/加载时间当成历史事件时间。旧计划也缺少源文件标识，补发的历史计划与新计划混在一起，造成重复复测的错觉。

暂停时还存在实际状态问题。自动审批/工程状态接口可能先建立 `kind=agent` 会话，复测继续仍在同一个会话中执行，但复测暂停接口固定要求 `kind=retest`，返回 `session kind mismatch`。用户界面保存了暂停，后台文件却仍显示运行。修复后按既有会话类型停止同一会话，并保存取消代数及原断点。

## 修改

- 从数字时间戳、ISO 时间或原生事件 ID 恢复真实事件时间，并按发生顺序排列历史。已有缓存记录也能迁移。
- 计划、工具和文件切换事件携带明确源文件。开始下一份通报有独立标题；计划侧栏在新文件开始时不再显示上一份的计划。
- 后台先提交精确文件的完成记录，再公布报告产物。报告已公布后发生暂停/重开，已完成文件不会再次作为待处理文件。
- 顶部常驻两条紧凑进度：总进度由后台精确已完成文件数计算；本份进度由读取、规划、工具核验、判定、报告、完成等阶段计算。阶段比例表示执行阶段，不是耗时估算。新文件开始时本份进度重置，生成报告时为90%，文件和报告完成后为100%。
- 报告显示为文件卡片，包含文件名、对应通报、历史时间及“打开报告”“打开文件夹”；完整位置可展开，显示时去除 Windows 扩展路径前缀。打开报告显式打开文件，原通用路径打开命令的默认文件夹行为保持兼容。
- 工作台保留左侧会话、中央对话、右侧详情。顶部只保留标题操作行和双进度带；完整暂停原因、目录统计、计划、最近报告放在右侧。右侧使用“计划与报告 / 操作队列 / 执行轨迹”标签，当前面板独占侧栏高度并独立滚动。左右侧栏可分别收起。
- “自动 / 工程 Agent / 复测 Agent”与自动审批常驻输入框上方。借鉴桌面聊天的空间分配，保留 KOI 的原有操作。
