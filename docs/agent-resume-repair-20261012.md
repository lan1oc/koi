# Agent 暂停与继续修复（2026-10-12）

后续 Python 静默执行、计划面板及 SSE 恢复已继续修复，原默认启动位置也已更新。当前交付与验证请参阅 `docs/agent-experience-fix-20261012.md`；下面保留上午那次修复的证据。

本次从失败会话 `session-1791766114590-pw8acx` 的后台状态、命令日志和 WebView2 缓存排查。原后台代数始终为 1，点击继续和发送继续时，日志只有状态查询，没有恢复请求。缓存序列化后有 4,852,998 字符；一份旧会话存在 22 条压缩摘要，大部分体积来自摘要元数据中反复复制的断点。缓存写入异常在 `setActiveRetestSession` 中抛出，阻断了之后的后台调用。

另一个故障来自原通报以 HTTP 格式标记 SSL 网站，而模型计划可能以 HTTPS 表达证书目标。计划校验使用普通 HTTP 同源规则，早于 TLS 工具的主机与端口规范化，导致合法证书核验也可能被误拦。旧错误没有记录被拒绝目标的具体来源，不能用它确认模型当时返回的完整计划。

## 变更

- 压缩后仅保留一条当前摘要，保留会话级的完整断点，不再将历史摘要的元数据重复嵌入新摘要。
- 会话缓存增加 IndexedDB 备份和启动恢复。localStorage 写入失败时保持完整内存状态及备份，继续向 Rust 提交操作；后台的队列和工具证据继续独立持久化。
- 继续按钮与通报会话的聊天继续使用同一条恢复流程，明确反馈状态查询及恢复情况，携带 `force_resume=true`、报告偏好与当前自动审批设置。切换工程模式也不改变已有通报任务的恢复路径。
- 规范化模型计划中的原通报目标：同主机的 TLS 表达恢复为原始通报 URL；相对路径仅在来源唯一时解析；保留授权端口，支持省略协议的明确目标。普通 HTTP 工具继续检查同源，额外主机或端口仍不执行。
- 目标校验反馈列出拒绝来源与原通报来源，隐藏查询参数中的敏感值，并指导模型修正计划或记录材料缺口。自动审批用于选择和批准当前任务范围内的工具。
