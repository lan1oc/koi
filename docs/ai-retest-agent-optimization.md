# AI 复测 Agent 优化记录（2026-09-21）

AI 模式由模型读取通报、列出问题、选择工具、观察实际返回并逐项给出结论。Rust 负责文件队列、目标范围、预算、断点和停止控制。下一份文件的调度使用确切源文件路径；每份通报的验证方法和判定仍交给模型。

本次接续工作区已有的 Rust Agent 实现，修复了运行闭环中的缺口：

- 将队列 `retest_queue` 与单文件 `resume_snapshot` 独立持久化。保存当前文件证据和压缩聊天记录时，保留剩余文件、报告偏好和已处理结果。
- 继续时优先恢复后端持久化断点，解开前端 `currentFile/resumeSnapshot` 和队列包装；证据不再经过会破坏深层类型的六层聊天裁剪器。仍检查源文件路径及摘要，敏感字段仍脱敏。
- 一份通报处理结束后自动调度下一份，避免文件数量受通用 Agent 的八次工具反思上限限制。最终反思获得完整、可解析的结果摘要、队列和工具定义。
- 模型格式或初始计划不完整时，最多自动修正两次，保留已有工具观察。达到轮次预算时暂停并保留断点；继续获得新的轮次额度，不清空已有证据及累计请求数。
- 同一工具调用的去重不受 `purpose` 文案以及默认 GET 参数写法影响；失败调用允许一次等价重试。每次工具执行具有独立事件标识，运行、失败、完成能对应同一张工具卡。
- 部分问题可复现、部分待核验时，整体保持风险状态，并保留未覆盖数量。未完成的项目不显示为已核验。
- 探针增加 Cookie 字典的 `get_dict()` / `set()` 和 `with requests.Session()` 支持。系统提示明确 `http_request`、`record` 是脚本已注入接口。
- 状态接口按实际文件完成情况返回进度；刚收到模型计划时不会把仍在运行的队列显示为 100%。队列还有文件而模型未安排操作时，保留可继续状态。

核心实现位于 `tauri-ui/src-tauri/src/backend/ai_retest.rs`、`retest_agent_state.rs`、`native_runtime.rs`、`probe_runner.rs`。前端结果展示位于 `tauri-ui/src/modules/ai-testing/TestWorkbenchPage.tsx`。

验证包括后端完整测试（384 通过、10 个环境测试默认跳过）、末轮 62 项运行时回归、真实 Windows AppContainer 的会话 Cookie 与停止测试，以及浏览器继续按钮、聊天输入继续、重连和停止丢弃迟到结果测试。新增回归覆盖十份通报连续执行、压缩并重启后直接恢复判定、深层证据类型保留、模型自动修正与等价请求去重。

真实模型联调使用隔离的本机 HTTP 接口与合成通报：GET 获取 nonce 和 Cookie，随后使用同一会话 POST，实际得到预设证明字段，模型判定可复现并生成 Word 报告。该场景验证了模型、HTTP 工具、Python 沙箱与报告的链路；并不代表所有漏洞类型和实际业务系统均已覆盖。

可运行程序放在 `dist-tauri/4.0.0/koi-agent-optimized/koi.exe`。目录包含完整依赖运行时，读取父级便携标记指向的现有 `dist-tauri/4.0.0/koi-data`。版本仍为 4.0.0，本地优化程序未作为正式发布版提交或发布。启动该程序前先退出旧版，以便接着使用原配置及会话。
