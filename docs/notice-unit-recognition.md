# 通报单位识别

分类、改写、单位目录判断和抄送匹配共用单位识别依据，单位名称不要求以“公司”“中心”等固定后缀结尾。

优先使用通报中明确的结构：`网络安全事件隐患通报第S20262445号_单位_问题.docx`，以及“关于单位所属网站存在某问题的通报”等标题。编号前的受管工作副本前缀会去掉，单位和问题分别读取。

其次使用分类数据库中的完整单位名，按完整名字和分隔边界匹配，保留无常见后缀、英文机构及联合体等名称。找不到明确文件名时，读取 Word 正文中的“单位名称”“企业名称”“机构名称”“被通报单位”等标签，或正文的完整通报标题。已识别的单位目录也用于通用文件名的处理。

原有常见后缀规则继续作为兼容方式，不能覆盖已经明确识别的单位。多个候选不能唯一确定时，不猜测其中一个；保留原件并提示需要核对。改写前仍无法确定单位时，停止文书生成和编号分配，避免生成“未知企业”文书。

分类只移动原文件，不改变内容。抄送仍只补写已带改写来源标记、且抄送为空或为占位符的文档。当前四阶段流程保留通报 Word 和处置模板用于人工调整，自动 PDF 阶段处理责令整改通知书；手动微调后可再执行通报 PDF 转换。
